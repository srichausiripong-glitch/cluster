# Cluster — ต้นแบบส่วนที่ผูกกับคลินิก

ต้นแบบที่กดได้ของ Cluster รุ่น 1 สำหรับนำเสนอ ไม่มีเซิร์ฟเวอร์และไม่มีข้อมูลจริง ทุกอย่างอยู่ในเบราว์เซอร์ของเครื่องที่เปิด

รอบที่ 1 ของการปรับ (พฤศจิกายน 2569) เปลี่ยนหน้าตาเป็นแนวป๊อปอาร์ต ใส่โลโก้ของเจ้าของโปรเจกต์ และเปลี่ยนแผนที่เป็นแผนที่จริงของกรุงเทพฯ สามระดับ เส้นทางข้อมูลยังเป็นของเดิมทั้งหมด ดูหัวข้อ "รอบที่ 1 เปลี่ยนอะไร" ด้านล่าง

## วิธีเปิด

```bash
npm install
```

```bash
npm run dev
```

แล้วเปิด http://localhost:5173

## นำขึ้น Vercel

ต้นแบบเป็นหน้าเว็บนิ่งทั้งหมด จึงนำขึ้น Vercel ได้โดยไม่ต้องมีเซิร์ฟเวอร์ ไฟล์ `vercel.json` ส่งทุกเส้นทางของหน้า (เช่น `/app/list`) ไปที่ `index.html` และใส่หัว `X-Robots-Tag: noindex` เพื่อไม่ให้เครื่องมือค้นหาเก็บหน้า เพราะเป็นต้นแบบที่ใช้ข้อมูลจำลอง

```bash
npx vercel link
```

```bash
npx vercel pull --yes --environment=production
```

```bash
npx vercel build --prod
```

```bash
npx vercel deploy --prebuilt --prod
```

คำสั่งชุดนี้ build ในเครื่องแล้วส่งขึ้นเฉพาะผลที่ build แล้ว โฟลเดอร์ `.vercel` และไฟล์ `.env*` ที่เครื่องมือสร้างไม่ถูกเก็บเข้า git ลิงก์ที่ได้เปิดได้ทุกคนที่มีลิงก์

## หน้าที่มี

| ที่อยู่ | คืออะไร |
|---|---|
| `/` | เวทีสาธิต: แอปฝั่งผู้ใช้ คอนโซลคลินิก และที่เก็บข้อมูลของแต่ละฝ่าย เรียงข้างกันและอัปเดตพร้อมกัน |
| `/app` | แอปฝั่งผู้ใช้ (มือถือ): แผนที่ รายการจุดบริการ ส่งสัญญาณ บอกต่อ ดูแลตัวเอง ช่วยเหลือ |
| `/r#…` | หน้าของผู้รับลิงก์ เนื้อหามาจากส่วนท้ายของลิงก์เท่านั้น |
| `/clinic` | คอนโซลคลินิก: ออกรหัส บันทึกผล ยอดรวมรายสัปดาห์ รหัส fast-track ช่วยแจ้งผู้สัมผัส |
| `/operator` | หลังบ้านผู้เผยแพร่: ไฟล์ประจำสัปดาห์ เรื่องร้องเรียน ข้อมูลที่เก็บ |
| `/data` | ข้อมูลอยู่ที่ไหน: สิ่งที่แต่ละฝ่ายถืออยู่ ลำดับเหตุการณ์ และตารางใครรู้อะไร |
| `/design` | สี ตัวอักษร และชิ้นส่วน UI |

ลิงก์ลัดสำหรับนำเสนอ: เติม `?seed=pilot` หรือ `?seed=threshold` เพื่อเริ่มจากข้อมูลสาธิต และ `?phase=2` เพื่อดูตัวอย่างสัญญาณระดับโซน เช่น `/?seed=threshold`

## ลำดับการนำเสนอ 8 ขั้น

เปิดหน้า `/` แล้วกด "ถัดไป" ทีละขั้น เวทีจะตีกรอบช่องที่ต้องทำในขั้นนั้นและเปิดหน้าที่ต้องใช้ให้

1. คอนโซลคลินิก → ออกรหัส → กดออกรหัสให้ผู้มาตรวจ
2. คอนโซลคลินิก → บันทึกผล → เลือกผลบวกให้รหัสนั้น
3. แอป → ส่งสัญญาณ → เลือกกลุ่มโรคเดียวกัน → มีรหัสจากคลินิก → ใส่รหัส
4. ติ๊ก "ให้คลินิกนับรวมเป็นสัญญาณของกรุงเทพฯ" → กด "ส่งให้คลินิกนับรวม" แล้วดูหน้าสรุป
5. กด "บอกต่อคนที่อาจเกี่ยวข้อง" → ตอบคำถามความปลอดภัย → ส่งลิงก์เอง → เลือกช่วงเวลา → สร้างลิงก์
6. กด "เปิดหน้าของผู้รับ" → ดูรายละเอียด
7. คอนโซลคลินิก → ยอดรวมรายสัปดาห์ → ส่งยอดรวม
8. คอลัมน์ข้อมูล → เผยแพร่ไฟล์สัปดาห์นี้ → ดูแผนที่ในช่องแอป

รายงานเดียวจะยังไม่ถึงเกณฑ์ 10 แผนที่จึงแสดง "ต่ำกว่าเกณฑ์" ซึ่งเป็นพฤติกรรมที่ตั้งใจ

ถ้าต้องการแสดงสภาพเมื่อมีรายงานพอ ให้เลือก "ถึงเกณฑ์ 10" ที่ "ข้อมูลเริ่มต้น" **ก่อน** เริ่มขั้นที่ 1 ปุ่มนี้ล้างข้อมูลสาธิต ใส่ยอดรวมจากคลินิกอื่นอีกสองแห่ง แล้วเผยแพร่ให้เอง รายงานที่ทำในขั้นที่ 1 ถึง 8 จะบวกเพิ่มเข้าไป ไม่ทับของเดิม

ปุ่ม "ข้ามไปสัปดาห์ถัดไป" ในคอลัมน์ข้อมูลใช้แสดงว่าสัญญาณเปลี่ยนอายุและหมดอายุเอง: จาก "ถึงเกณฑ์ 10" กด 1 ครั้งจะเป็น "ผสม" กดครบ 4 ครั้งจะเหลือ "ต่ำกว่าเกณฑ์" และครบ 12 ครั้งจะเป็น "ยังไม่มีข้อมูล" พร้อมกับที่ยอดรวมบนเซิร์ฟเวอร์ถูกลบ

ระหว่างนำเสนอ ถ้าช่องแอปค้างอยู่ที่หน้าว่าง (หลังกด "ออกเร็ว") หรือหน้าของผู้รับ ให้กด "กลับไปแผนที่" เหนือช่องนั้น

## สิ่งที่จำลอง

- ที่เก็บข้อมูล 4 ฝ่าย (เครื่องผู้ใช้ คลินิก เซิร์ฟเวอร์ ไฟล์ที่เผยแพร่) คือคีย์แยกกันใน `localStorage` ของเบราว์เซอร์เดียว
- จุดบริการทั้งหมดเป็นชื่อสมมติ และตัวเลขทางการเป็นตัวเลขสมมติ
- แผนที่ฐานเป็นข้อมูลจริง แต่หมุดจุดบริการวางในตำแหน่งสมมติ ห่างจากคลินิกและโรงพยาบาลจริงอย่างน้อย 60 เมตร และสัญญาณระดับโซนใน "ตัวอย่างเฟส 2" เป็นข้อมูลตัวอย่าง
- รหัส fast-track รายสัปดาห์คำนวณด้วยแฮชธรรมดา ไม่ใช่ความลับ
- การตรวจรหัสคลินิกในแอปอ่านที่เก็บของคลินิกโดยตรง แทนบริการตรวจรหัสจริง แอปได้คำตอบแค่ว่ารหัสมีอยู่จริงไหม ไม่ได้ผลตรวจ
- ข้อความทางคลินิกเป็นร่าง ยังไม่มีแพทย์ลงนาม

## แผนที่

แผนที่เป็นข้อมูลจริงจาก OpenStreetMap (สัญญาอนุญาต ODbL) อ่านจากแผ่นแผนที่ของ OpenFreeMap ในรูปแบบ OpenMapTiles แล้วแปลงเป็นไฟล์ใน `public/map/` ล่วงหน้า แอปไม่เรียกบริการแผนที่ใดขณะใช้งาน บรรทัดเครดิตบนแผนที่คือ "© ผู้ร่วมสร้าง OpenStreetMap · OpenMapTiles"

| ระดับ | ไฟล์ | ครอบคลุม |
|---|---|---|
| ทั้งเมือง | `city.json` | กรุงเทพฯ และจังหวัดรอบข้าง: ทางด่วน ถนนสายหลัก แม่น้ำ ทะเล เส้นเขต |
| ย่าน | `district/*.json` (6 ไฟล์) | ใจกลางเมืองกว้างราว 9.5 กม. ยาวราว 14 กม. เหนือสุดแถวสะพานควาย ใต้สุดแถวราษฎร์บูรณะ ตะวันตกแถวพระนคร ตะวันออกแถวพระโขนง: ถนนทุกสาย คลอง สวน รถไฟฟ้า ชื่อสถานี |
| ซอย | `street/*.json` (3 ไฟล์) | แนวเหนือใต้กว้างราว 2.4 กม. ยาวราว 7 กม. จากอนุสาวรีย์ชัยฯ ผ่านราชเทวี ปทุมวัน สีลม ลุมพินี ถึงสาทร: ตึก ชื่อถนนและซอย |

การใช้งานบนแผนที่

- ลากด้วยนิ้วเดียวเพื่อเลื่อน แตะสองครั้ง กางสองนิ้ว หรือกดปุ่ม + เพื่อเข้าไปหนึ่งระดับ หุบสองนิ้วหรือกดปุ่ม − เพื่อออกหนึ่งระดับ มีสามระดับเท่านั้น ไม่มีการซูมแบบต่อเนื่อง
- แผนที่อยู่ในพื้นที่ที่มีไฟล์เสมอ จึงไม่มีจอว่าง ปุ่ม + กดได้เฉพาะเมื่อระดับถัดไปมีแผนที่อยู่ในจอ ถ้าไม่มี แผนที่บอกว่า "ต้นแบบยังไม่มีแผนที่ระดับถัดไปตรงนี้"
- สัญญาณอยู่ที่ระดับโซนทุกระดับการซูม เม็ดสีม่วงใหญ่ขึ้นตามระดับของสัญญาณ ไม่ได้ชี้ถนนหรือตึกใด
- ถ้าโหลดไฟล์แผนที่ไม่ได้ โซน หมุด และแผ่นข้อมูลยังใช้ได้
- แผนที่วาดเฉพาะส่วนที่อยู่ในจอ บนเครื่องที่วาดไม่ทันนิ้ว ภาพเดิมจะเลื่อนตามนิ้วก่อน แล้ววาดใหม่เมื่อนิ้วหยุดหรือปล่อย

ไฟล์รวมต้องไม่เกิน 12 MB (ตอนนี้ราว 6 MB) และมีการทดสอบกำกับ

ป้ายบนแผนที่มีเฉพาะถนน ซอย สถานีรถไฟฟ้า สวน ทางน้ำ ชื่อเขต เมืองรอบข้าง สถานที่ราชการ และศาสนสถาน กติกาอยู่ใน `scripts/map/classify.ts` ชื่อร้าน โรงแรม สถานบันเทิง คลินิก และโรงพยาบาลไม่ถูกนำมาใส่

สร้างไฟล์แผนที่ใหม่ (ต้องต่ออินเทอร์เน็ต):

```bash
npm run map:fetch
```

```bash
npm run map:build
```

โซนทั้งหกคือกลุ่มเขตของกรุงเทพฯ วาดจากเส้นเขตจริง รายชื่อเขตในแต่ละกลุ่มใน `scripts/map/build.ts` เขียนจากความจำ ต้องตรวจกับประกาศของ กทม. ก่อนใช้จริง

## โลโก้

โลโก้ที่หัวแอปคือภาพ `src/design/logo/mark.png` และ `src/design/logo/word.png` ซึ่งตัดจากไฟล์โลโก้ของเจ้าของโปรเจกต์ด้วย `scripts/logo/cut.py` ไฟล์ต้นทางไม่ได้อยู่ใน repo นี้ และยังไม่มีไฟล์เวกเตอร์

```bash
python3 scripts/logo/cut.py <ไฟล์โลโก้ต้นทาง.png> src/design/logo
```

## รอบที่ 1 เปลี่ยนอะไร

สิ่งที่เปลี่ยน

- หน้าตาทุกหน้าเป็นแนวป๊อปอาร์ต: สีชมพู เหลือง เขียวจากโลโก้ เส้นขอบดำ เงาแข็ง สีม่วงใช้กับสัญญาณเท่านั้น ไม่มีสีแดง กติกาอยู่ใน `DESIGN.md` และมีชุดทดสอบ `src/design/look.test.ts` ตรวจกับโค้ดทุกไฟล์
- โลโก้ของเจ้าของโปรเจกต์แทนตัวอักษรเดิมทุกที่
- แผนที่จริงสามระดับแทนแผนผังที่วาดเอง สัญญาณเป็นเม็ดสีม่วงบนพื้นแผนที่ อายุของสัญญาณบอกด้วยลักษณะเส้นขอบ
- การเคลื่อนไหวเล็กน้อย: เม็ดสีของโซนที่เพิ่งรายงานขยายและหดช้า ๆ หมุดเด้งขึ้นครั้งเดียว ปุ่มส่งสัญญาณมีวงคลื่น ทั้งหมดหยุดเมื่อเครื่องตั้งค่าลดการเคลื่อนไหว
- ในตัวอย่างเฟส 2 เมื่อซูมเข้าไป กล่องสถานะสีเหลืองบอกชื่อโซนที่อยู่กลางจอแทนคำว่ากรุงเทพฯ
- จุดเล็กที่แก้ตามการตรวจหน้าตาและการลองใช้งาน: ลิงก์ที่สร้างในขั้นตอนบอกต่อเลื่อนขึ้นมาให้เห็นและบอกผลของการคัดลอก หน้า "ดูแลตัวเอง" มีทางไปขั้นตอนบอกต่อ ใบสรุปบอกว่าการ์ดที่เก็บไว้ก่อนหน้ายังอยู่ในเครื่อง และวันที่เขียนแบบไทย

สิ่งที่ยังเป็นของเดิม

- เส้นทางข้อมูลทั้งหมด: แอปตรวจรหัสกับคลินิก ความยินยอมให้นับรวมบันทึกที่คลินิก คลินิกส่งยอดรวมรายสัปดาห์ และสัญญาณบนแผนที่มาจากยอดรวมนั้นเท่านั้น
- รหัส fast-track การช่วยแจ้งผู้สัมผัสโดยคลินิก คอนโซลคลินิก หลังบ้านผู้เผยแพร่ และลำดับการนำเสนอ 8 ขั้น
- สถานะ "ไม่มีคลินิกพาร์ตเนอร์" ยังอยู่บนแผนที่

ข้อจำกัดของรอบนี้

- ยังไม่ได้ลองบนโทรศัพท์จริง ตรวจด้วยเบราว์เซอร์บนคอมพิวเตอร์ที่ขนาดจอ 390 × 844 และ 320 × 640
- ปุ่ม "ออกเร็ว" พาไปหน้าว่างทันที แต่การกดย้อนกลับหนึ่งครั้งในเบราว์เซอร์ยังเปิดหน้าก่อนหน้าของแอปได้ เป็นข้อจำกัดที่มีมาก่อนรอบนี้และยังไม่ได้แก้
- หลังเปิดดูหน้าของผู้รับจากขั้นตอนบอกต่อ การกดย้อนกลับจะเริ่มขั้นตอนบอกต่อใหม่ ลิงก์ที่สร้างไว้หาย
- แนวป๊อปอาร์ตยังไม่ได้ทดสอบกับผู้ใช้ ทั้งเรื่องความน่าไว้ใจและการอ่านเม็ดสี
- รายชื่อเขตของแต่ละโซนเขียนจากความจำ ต้องตรวจกับประกาศของ กทม.
- แผนที่ระดับย่านและระดับซอยมีเฉพาะพื้นที่ในตารางด้านบน

## สิ่งที่รุ่นจริงต้องมี

ดูแผนผลิตภัณฑ์ของ Cluster (เอกสารภายใน ไม่ได้อยู่ใน repo นี้) หัวข้อกฎหมาย และหัวข้อเฟสกับประตู โดยเฉพาะ

- คำตอบของหน่วยงานเรื่องการเก็บข้อมูลจราจร
