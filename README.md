# Cluster

แอปสำหรับผู้ใช้จริงรุ่น 1: แผนที่จุดตรวจโรคติดต่อทางเพศสัมพันธ์ในกรุงเทพฯ การบอกต่อคู่ด้วยลิงก์ และสัญญาณราย 50 เขตจากรายงานของผู้ใช้เอง ข้อกำหนดอยู่ที่ `docs/superpowers/specs/2026-11-12-cluster-launch-v1-design.md` (เอกสารภายใน ไม่อยู่ใน repo สาธารณะ)

ต้นแบบสำหรับนำเสนอ (เวที คอนโซลคลินิก ข้อมูลสาธิต) อยู่ที่ป้าย git `prototype-r1` และลิงก์ `cluster-prototype.vercel.app`

## วิธีเปิดในเครื่อง

```bash
npm install
```

```bash
npm run dev
```

แล้วเปิด http://localhost:5173 หน้าแอปทำงานได้โดยไม่มีเซิร์ฟเวอร์ แต่การส่งซองและไฟล์ที่เผยแพร่ต้องมีฟังก์ชันของ Vercel (`npx vercel dev`)

## หน้าที่มี

| `/r#…` | หน้าของผู้รับลิงก์ เนื้อหามาจากส่วนท้ายของลิงก์เท่านั้น |
| `/privacy` `/terms` | นโยบายความเป็นส่วนตัว และข้อตกลงการใช้ |
| `/transparency` | รายงานความโปร่งใส: การตัดสินใจของผู้ทบทวนพร้อมชื่อ และจำนวนซองต่อสัปดาห์ |

## เส้นทางของรายงาน

1. ผู้ใช้กด "เช็กอิน" บนหน้าแผนที่เมื่อไปเช็กมาแล้วไม่เจออะไร (ไม่เกิน 1 ครั้งใน 4 สัปดาห์ เครื่องจำเขตไว้ใช้ครั้งต่อไป) หรือกด "ส่งสัญญาณ" แล้วเลือก "ตรวจแล้วพบเชื้อ" หรือ "มีอาการ ยังไม่ได้ตรวจ" ขึ้นแผนที่ได้ คือการเช็กอิน ผลจากคลินิกหรือแล็บของหนองในและคลามิเดียหรือซิฟิลิส และ "มีอาการ" (ไม่เกิน 1 ครั้งใน 4 สัปดาห์ นับแยกจากผลยืนยัน) หลังเลือกเขตเองจาก 50 เขต
2. รายงานรอในเครื่อง ทุกเครื่องที่เปิดแอปส่งซองสัปดาห์ละ 1 ใบในเวลาสุ่ม ซองขนาดเท่ากัน เข้ารหัสด้วยกุญแจสาธารณะของเซิร์ฟเวอร์ และต้องคำนวณงานราว 10 วินาทีก่อนส่ง ซองที่ไม่มีรายงานจริงมีรายงานสุ่มด้วยความน่าจะเป็น 0.002
3. เซิร์ฟเวอร์ (`api/envelope.ts`, `server/intake.ts`) เปิดซอง บวกยอดของ (เขต ชนิด สัปดาห์) แล้วทิ้งซอง นับไม่เกิน 30 รายงานต่อกลุ่มเครือข่ายต่อสัปดาห์
4. ทุกวันจันทร์ 03:00 เวลากรุงเทพฯ งานประจำสัปดาห์ (`api/cron/publish.ts`, `server/publish.ts`) หักรายงานสุ่ม ใช้เกณฑ์ 10 บวกระยะเผื่อ พักยอดที่พุ่งผิดปกติไว้ให้ผู้ทบทวนสองคน แล้วเผยแพร่ไฟล์เดียวที่ทุกเครื่องอ่าน และลบยอดเก่ากว่า 12 สัปดาห์

## ตัวตรวจก่อนขึ้นจริง

`npm run launch-check` รันก่อนทุก build บน Vercel และไม่ยอมให้ build ผ่านถ้า: ไม่มีจุดบริการเลย หรือมีจุดที่ไม่บอกที่มา (https) หรือวันที่ดึงข้อมูล หรือจุดที่ยืนยันแล้วไม่บอกวันที่ ผู้ยืนยัน และวิธี · มีข้อความทางการแพทย์ใน `src/copy/clinical.ts` ที่ไม่มีลิงก์ที่มา https จากผู้เผยแพร่ในรายชื่อ `SOURCE_HOSTS` · ตัวแปรข้างบนไม่ครบ · ผู้ทบทวนน้อยกว่า 2 คน ลิงก์ทดสอบ (preview) ตั้ง `LAUNCH_CHECK_PREVIEW=1` เพื่อข้ามเงื่อนไขเรื่องข้อมูลได้ แต่ production ข้ามไม่ได้

- จุดบริการ: `src/data/care-points.json` (รายชื่อเดิม) `src/data/bma-health-centres.json` `src/data/bma-hospitals.json` และ `public/care/pharmacies.json` ทุกจุดมีลิงก์ที่มา (`source`) และวันที่ดึงข้อมูล (`fetched`) จุดที่ยืนยันแล้วมีช่อง `verified` (วันที่ ผู้ยืนยัน วิธี) และจุดรับ PEP ต้องยืนยันทางโทรศัพท์ จุดที่ยังไม่ยืนยันขึ้นในแอปเป็นจุดเล็ก "โทรถามก่อนไป" ไม่ใช่หมุดใหญ่
- ข้อความทางการแพทย์: `src/copy/clinical.ts` แต่ละข้อเป็นคำแนะนำทั่วไป มี `source` (ชื่อและลิงก์ของหน้าที่รองรับ) จากกรมควบคุมโรค WHO CDC คณะแพทย์ หรือศูนย์วิจัยโรคเอดส์ สภากาชาดไทย แก้ถ้อยคำเมื่อไรให้เปิดหน้าที่มาดูว่ายังตรงกัน

## สิ่งที่ Vercel เก็บ

ตามเอกสาร Runtime Logs ของ Vercel (อ่านเมื่อ 12 พฤศจิกายน 2569, https://vercel.com/docs/logs/runtime) Vercel เก็บบันทึกการเรียกใช้ไว้ 1 ชั่วโมงในแผน Hobby และ 1 วันในแผน Pro บันทึกมีเวลา หน้าที่เรียก ชื่อเบราว์เซอร์ และใช้ที่อยู่ IP ในการค้นหา และไม่มีวิธีปิดที่เอกสารระบุ แอปไม่เปิด Analytics, Speed Insights หรือ Log Drain และฟังก์ชันไม่พิมพ์เนื้อหาซองหรือที่อยู่ลงบันทึก (มีชุดทดสอบกำกับ) หน้า `/privacy` บอกเรื่องนี้กับผู้ใช้

## แผนที่

แผนที่เป็นข้อมูลจริงจาก OpenStreetMap (สัญญาอนุญาต ODbL) อ่านจากแผ่นแผนที่ของ OpenFreeMap ในรูปแบบ OpenMapTiles แล้วแปลงเป็นไฟล์ใน `public/map/` ล่วงหน้า แอปไม่เรียกบริการแผนที่ใดขณะใช้งาน บรรทัดเครดิตบนแผนที่คือ "© ผู้ร่วมสร้าง OpenStreetMap · OpenMapTiles"

| ระดับ | ไฟล์ | ครอบคลุม |
|---|---|---|
| ทั้งเมือง | `city.json` | กรุงเทพฯ และจังหวัดรอบข้าง: ทางด่วน ถนนสายหลัก แม่น้ำ ทะเล เส้นเขต |
| เขต | `district/*.json` (6 ไฟล์) | ใจกลางเมืองกว้างราว 9.5 กม. ยาวราว 14 กม. เหนือสุดแถวสะพานควาย ใต้สุดแถวราษฎร์บูรณะ ตะวันตกแถวพระนคร ตะวันออกแถวพระโขนง: ถนนทุกสาย คลอง สวน รถไฟฟ้า ชื่อสถานี |
| ซอย | `street/*.json` (3 ไฟล์) | แนวเหนือใต้กว้างราว 2.4 กม. ยาวราว 7 กม. จากอนุสาวรีย์ชัยฯ ผ่านราชเทวี ปทุมวัน สีลม ลุมพินี ถึงสาทร: ตึก ชื่อถนนและซอย |

การใช้งานบนแผนที่

- ลากด้วยนิ้วเดียวเพื่อเลื่อน แตะสองครั้ง กางสองนิ้ว หรือกดปุ่ม + เพื่อเข้าไปหนึ่งระดับ หุบสองนิ้วหรือกดปุ่ม − เพื่อออกหนึ่งระดับ มีสามระดับเท่านั้น ไม่มีการซูมแบบต่อเนื่อง
- แผนที่อยู่ในพื้นที่ที่มีไฟล์เสมอ จึงไม่มีจอว่าง การเข้าไปหนึ่งระดับทำได้เฉพาะตรงที่มีแผนที่ระดับถัดไป ถ้าไม่มี แผนที่อยู่ที่เดิมและบอกว่า "ยังไม่มีแผนที่ระดับถัดไปตรงนี้" ไม่พาไปที่อื่น ยกเว้นปุ่ม + จากระดับทั้งเมือง ซึ่งพาไปใจกลางเมืองที่มีแผนที่
- สัญญาณอยู่ที่ระดับเขตทุกระดับการซูม เม็ดสีม่วงใหญ่ขึ้นตามระดับของสัญญาณ ไม่ได้ชี้ถนนหรือตึกใด เขตที่ยังไม่ถึงเกณฑ์ไม่มีเครื่องหมาย
- ไฟล์แผนที่ระดับเขตและระดับซอยทั้งเก้าไฟล์โหลดพร้อมกันครั้งเดียวเมื่อออกจากระดับทั้งเมืองครั้งแรก บันทึกของเครื่องที่ให้บริการไฟล์จึงบอกไม่ได้ว่าใครดูส่วนไหนของเมือง
- ถ้าโหลดไฟล์แผนที่ไม่ได้ แผนที่บอกหนึ่งบรรทัด เขต หมุด และแผ่นข้อมูลยังใช้ได้ และไฟล์ที่โหลดไม่ได้จะลองใหม่เมื่อเปลี่ยนระดับ
- แผนที่วาดเฉพาะส่วนที่อยู่ในจอ บนเครื่องที่วาดไม่ทันนิ้ว ภาพเดิมจะเลื่อนตามนิ้วก่อน แล้ววาดใหม่เมื่อนิ้วหยุดหรือปล่อย

ไฟล์รวมต้องไม่เกิน 12 MB (ตอนนี้ราว 6 MB) และมีการทดสอบกำกับ

ป้ายบนแผนที่มีเฉพาะถนน ซอย สถานีรถไฟฟ้า สวน ทางน้ำ ชื่อเขต เมืองรอบข้าง สถานที่ราชการ และศาสนสถาน กติกาอยู่ใน `scripts/map/classify.ts` ซึ่งตรวจทั้งประเภทและชื่อ ป้ายที่มีคำว่าโรงพยาบาล คลินิก โรงแรม หรือชื่อสถานบันเทิงถูกตัดออกแม้จะเป็นชื่อสถานีหรือชื่อซอย และมีชุดทดสอบตรวจชื่อในไฟล์ที่สร้างแล้ว ชื่อร้าน โรงแรม สถานบันเทิง คลินิก และโรงพยาบาลไม่ถูกนำมาใส่

สร้างไฟล์แผนที่ใหม่ (ต้องต่ออินเทอร์เน็ต):

```bash
npm run map:fetch
```

```bash
npm run map:build
```

พื้นที่บนแผนที่คือ 50 เขตของกรุงเทพฯ (`src/domain/districts.ts`) วาดจากเส้นเขตจริงใน OpenStreetMap รหัสเขตอยู่ในซองและในตาราง จึงห้ามเปลี่ยนหลังเปิดใช้จริง

## จุดบริการ

จุดบริการมี 4 ชั้น (คลินิกตรวจโรคทางเพศสัมพันธ์ · ศูนย์บริการสาธารณสุข กทม. · โรงพยาบาล · ร้านยา) และ 2 ระดับความเชื่อถือ: จุดที่ยืนยันแล้วเป็นหมุดใหญ่พร้อมรายละเอียดเต็ม จุดที่ยังไม่ยืนยันเป็นจุดเล็ก "โทรถามก่อนไป" พร้อมที่มาและวันที่ดึงข้อมูล

```bash
npm run care:fetch
```

ดึงรายชื่อศูนย์บริการสาธารณสุขและโรงพยาบาลจากข้อมูลเปิดกรุงเทพมหานคร (data.bangkok.go.th) และร้านยาจาก OpenStreetMap (ผ่าน Overpass) ครั้งเดียวตอนสร้าง แล้วเขียนเป็น `src/data/bma-health-centres.json` กับ `src/data/bma-hospitals.json` (รวมไปกับแอป) และ `public/care/pharmacies.json` (แอปอ่านจากเซิร์ฟเวอร์ของเราเมื่อเปิดชั้นร้านยาเท่านั้น) คำขอใช้ชื่อโปรแกรมกลางๆ `care-data-script/1.0` และไม่ส่งข้อมูลโปรเจกต์หรือผู้ใช้ จุดที่รายชื่อเดิมมีอยู่แล้วจะไม่ซ้ำ ไฟล์ร้านยาดัดแปลงจาก OpenStreetMap และเผยแพร่ภายใต้ ODbL (`public/care/LICENSE.md`)

```bash
npm run map:neighbours
```

อบรายชื่อเขตที่ติดกันจากเส้นเขตลง `src/map/data/neighbours.json` คำว่า "ใกล้" ในแอปหมายถึงเขตเดียวกันหรือเขตติดกัน แอปไม่ขอตำแหน่งของเครื่อง

## การแจ้งเตือน (ติดตามเขตของฉัน)

คนที่กด 🔔 ติดตามได้ 1 เขต เครื่องส่งแค่ที่อยู่สำหรับส่งแจ้งเตือนมาที่ `POST /api/push` ไม่ส่งเขต ตาราง `push_subscriptions` เก็บที่อยู่กับวันที่สมัครเท่านั้น ไม่มีเขต ไม่มีที่อยู่ IP การเปลี่ยนเขตที่ติดตามทำในเครื่องอย่างเดียว

ทุกวันจันทร์ 12:00 เวลาไทย (`/api/cron/notify`) เซิร์ฟเวอร์ส่งข้อความว่างที่เหมือนกันทุกเครื่อง เฉพาะเมื่อประกาศผลตอน 03:00 สำเร็จ service worker (`public/sw.js`) ดึง `/api/published` แล้วเทียบเขตที่ติดตามในเครื่อง ข้อความมีแค่ "Cluster · เขตที่คุณติดตามมีอัปเดต" หรือ "Cluster · แผนที่สัปดาห์นี้อัปเดตแล้ว" ไม่มีชื่อเขตหรือชื่อโรค แตะแล้วเปิด `/app#follow`

```bash
npm run make-vapid
```

พิมพ์กุญแจส่วนตัวสำหรับ `VAPID_PRIVATE_JWK` ใส่ใน Vercel อย่างเดียว ห้าม commit บน iPhone ต้องเพิ่มแอปไปยังหน้าจอโฮมก่อนจึงรับแจ้งเตือนได้

## โลโก้

โลโก้ที่หัวแอปคือภาพ `src/design/logo/mark.png` และ `src/design/logo/word.png` ซึ่งตัดจากไฟล์โลโก้ของเจ้าของโปรเจกต์ด้วย `scripts/logo/cut.py` ไฟล์ต้นทางไม่ได้อยู่ใน repo นี้ และยังไม่มีไฟล์เวกเตอร์

```bash
python3 scripts/logo/cut.py <ไฟล์โลโก้ต้นทาง.png> src/design/logo
```

## การทดสอบ

```bash
npm test
```

ชุดทดสอบครอบทั้งแอปและเซิร์ฟเวอร์ ส่วนเซิร์ฟเวอร์ทดสอบกับ Postgres จริงในหน่วยความจำ (PGlite) รวมกติกาหลัก: ซองทุกใบขนาดเท่ากัน ฐานข้อมูลไม่มีคอลัมน์ที่เก็บที่อยู่หรือเนื้อหาซอง บันทึกไม่มีที่อยู่ เกณฑ์ 10 และการหักรายงานสุ่ม คิวพักยอดและการทบทวนสองคน สวิตช์ปิดรับ การลบยอดเก่า และออกเร็วแล้วย้อนกลับไม่เข้าแอป ทิศทางการออกแบบอยู่ใน `DESIGN.md`
